# 需求 1：morph 内容缩小呈现方式

> 独立需求文档，可直接单独发给分析方。

## 现状（v2 架构，当前已回滚到这个状态）

动画结构（`LyricsMorphOverlay.kt`，progress p: 0=卡片, 1=全屏，全部视觉属性是 p 的纯函数）：

- **窗口层**：纯色圆角矩形（专辑取色背景），graphicsLayer 非等比缩放从全屏形变到歌词卡片矩形。零内容，只承载色块几何形变。
- **内容层**：真 LyricsScreen，全屏原生布局、**不缩放**，是窗口层的兄弟层（不在其变换子树内）。带三件东西：
  - 透明度交叉淡化（fracRange(p, 0.40, 0.65)）
  - 锚行位移跟踪 translationY（当前播放行随窗口从卡片中心升到屏幕中心）
  - drawWithContent clipRect 裁剪到窗口当前矩形（内容只在窗口内可见）

收起动画视觉：**窗口非等比形变（全屏矩形 → 卡片矩形）+ 内容 clipRect 渐进裁剪 + 内容淡出**。
展开动画是反函数。

已做帧率优化：组合零订阅 progress（snapshotFlow 一次性门）、artBg 改 ArtCache 直读、
逐帧视觉全走 graphicsLayer 延迟读。

## 需求

保持上一版窗口运动样式**不动**，只做两件事：
1. 帧率进一步提高
2. 内容在动画中的"缩小呈现方式"改善——现呈现方式（clipRect 渐进遮挡+淡出）被用户嫌不好看，想要"内容跟着窗口一起缩小"的观感（应用窗口拉大拉小的隐喻）。
   **已否决**："整窗等比缩放"方案（末段窄高窗摊开到扁卡片，观感差，用户评价"很难看"）。

**核心矛盾（务必先解决，这是决定方案能不能成立的前提）：**

内容层如果加等比 scale，缩放曲线要保证"任意时刻，内容的可见区域都被窗口矩形完整覆盖或者精确贴合"，不能出现"内容缩得比窗口小、四周露出窗口色块的空隙"，也不能"内容缩得比窗口大、必须硬裁剪出可见的边缘"（后者其实就是退化回"裁剪遮挡"的观感，等于没解决问题）。给出具体的缩放比例函数：应该以窗口矩形的宽方向为基准、还是高方向为基准、还是某种复合值，为什么，并用起点（p=0，卡片态，1096×359）和终点（p=1，全屏态，1264×2780）两个已知矩形代入验证一遍，看看中间过程（比如 p=0.5 时）内容尺寸和窗口尺寸是否贴合。
