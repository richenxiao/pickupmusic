## 1. 歌词"未找到"（《古惑仔》《开波》）— 你已验过 ✅

根因：请求参数 `lv=1` 时部分歌返回空 lrc 且无 yrc，`lv=-1` 正常。已改 `lv=-1`。

## 2. 部分歌手头像空框 — 你已验过 ✅

根因：Discogs 图片 URL 签名过期 → 403，而下载代码不校验状态码，把 403 错误页当图片写进磁盘缓存
→ 该分辨率桶永久解不开。修了三处：非 2xx 不落盘 / 坏字节自动清除 / **加载失败→清缓存重新解析**（自愈）。
补充验证（可选）：把网络断开再打开统计页，头像应从本地缓存正常显示。

## 3. 迷你播放条歌手名被硬裁 — **待验**

- 步骤：播放任意歌手名较长的歌（如 揽佬SKAI ISYOURGOD）。
- 预期：迷你条歌手名**带省略号**（"揽佬SKAI ISYOURG…"），而不是无声地只剩前半截。
- 根因：歌名那行有 `Ellipsis`、歌手那行只有 `maxLines=1`（Compose 默认 `Clip`）。

## 4. 拾光人格 v2 — **待验（体感）**

重点看这几点是否"过头或不足"：
- 夸它一句 → 应有轻微嘴硬/不自然，但**不该每句都来一次**；
- 随便闲聊 → 不该公式化成"冷淡+颜文字"模板；
- 让它做件事 → 不该自我介绍式复述功能清单。
- 单一真源：人格只在 `AgentEngine.persona`，两条链路共用（改人格只改这一处）。

## 5. 翻译按钮三档滑动控件 — **待验**

- 位置：设置 → 歌词本 → 翻译 分组，第一项「翻译按钮显示」。
- 预期：标题 + 副标题「根据外文数量决定是否开启」+ **三段式离散滑动控件**（不显示 / 外文较多时显示 /
  检测到外文就显示）；**拖动跟手、松手吸附到最近档**，不存在停在两档之间；点某段也能选中。
- 默认值应仍是「外文较多时显示」（老用户行为不变）。
- 逻辑确认：设成「不显示」→ 外语歌歌词页不应出现翻译按钮；设成「检测到外文就显示」→ 中文歌夹一个
  英文单词也应出现按钮（自动翻译仍按原占比阈值走，不受此档影响）。

## 6. 音乐自主选曲 + 搜索归一化 — **待验**

| 你说 | 预期 | 看什么日志 |
|---|---|---|
| 「你自己挑一首」 | **先搜库、自己挑、直接播**，绝不反问歌名 | `discover_music: mood=… → 候选 N 首`、`play_track: 《…》` |
| 「今天早上天气很好，挑一首」 | 让模型把处境联想成"可能出现在曲名里的词"（朝/夜明け/morning…）再搜库 | `mood 检索:「…」→ 概念 […] → 命中 N 首` |
| 「放一下《カブトムシ》」/「…kabutomushi」/「…独角仙」 | 应归到**同一首** | `play_track` 或 `playTracks` |
| 「库里有没有 X」 | 只回答，不播放 | `plan: skill=library_query` |

**明确指令不能弹卡片**（防过度提问）：逐条试「暂停」「下一首」「放一下《カブトムシ》」→ 应直接执行；
若日志出现 `clarify:` 行 = 我放宽过头了，需要收紧。

已知缺口（如实记录）：
- **汉字歌名的罗马字查询不覆盖**（按 `kakeru` 找「駆ける」需要 Kuromoji 读音索引，本版未接）；
- 译名兜底（独角仙→カブトムシ）依赖已配置 LLM；没配 key 时退化为纯本地（假名/罗马字仍可用）。

## 7. clarify 选择卡片 — **待验**

- 触发：① `clarify自检` 强制触发（见上）；② 真实对话里模型自己觉得该问时。
- 交互逐条验：
  - 点选项 → 选项文字作为**一条正常用户消息**出现，卡片收起，模型接着执行；
  - × / 「跳过」→ 卡片收起，**对话不卡死**（这一轮模型已返回，不存在"等待选择"态）；
  - 点「其他/我自己说」→ 焦点跳到真正的输入框、卡片**留着**（问题还看得见）；直接打字发送 = 选了「其他」，卡片自动收起；
  - 卡片期间输入框占位应为「或直接回复…」。
- 视觉：按下选项时应有 accent 描边 + 略深底色 + 徽章反色（移动端无键盘导航，所以高亮落在按下态）。
- **已知未验证**：卡片 UI 从未真机跑过，间距/圆角/高亮强度大概率需要微调。

## 8. Memory P1（数据层）— **待验：只验"不崩"**

P1 按定调**不接入对话链路**、无 UI、无提示词改动，所以没有可操作的界面行为可验。
唯一需要验的是**数据库迁移**：这批改动把 DB 版本从 24 提到 25，新增两张表
（`agent_memory` + `agent_memory_fts`）。迁移 DDL 是从 Room 自己生成的 schema 逐字抄的，
但**没有真机跑过**。

- 步骤：**直接覆盖安装**（不要先卸载——要复现"老库升级"路径），然后打开 App。
- 预期：能正常进主界面，**不闪退**。
- 若闪退：`adb logcat | grep -iE "Migration|Room|IllegalStateException"`，
  会明确说"Migration didn't properly handle: agent_memory"之类 → 把日志给我，我改迁移 SQL。
- 之后可顺手确认：库里已有的歌/歌单/设置都还在（迁移不会动老表）。

> 说明：P1 阶段这两张表**没有任何读写方**（RoomMemoryStore 只提供实现、谁都不 new 它）。
> 所以即使迁移有问题，表现也是"启动即崩"这种**响亮**的失败，不会是静默的数据损坏。
